- Register the node's public QUIC address on-chain (ADR 019 Phase 2 is a manual
  operator step). Inside the pod the node sees only its pod IP, so peers that
  read the registry learn the address from its on-chain multiaddrs; without
  them, inbound goes through hole-punching and relays. Off-cluster, against the
  same keystore (add your --config, --rpc-url and --keystore-password-file: the

{{- if eq $type "LoadBalancer" }}

     LB_IP=$(kubectl -n {{ $ns }} get svc {{ $name }} -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
     : "${LB_IP:?no load-balancer IP yet: re-run once kubectl get svc shows one}"
{{- else if and (eq $type "NodePort") (not .Values.service.nodePort) }}

     NODE_PORT=$(kubectl -n {{ $ns }} get svc {{ $name }} -o jsonpath='{.spec.ports[0].nodePort}')
{{- end }}

     # Not registered yet: stake and register with the address (check the
     # plan with --dry-run, then run it again without).
     decdn setup --mbps <MBPS> --region {{ $region }}{{ $flags }} --dry-run
     # Already registered: replace the whole registered set. The node must be
     # active, and a governance-set cooldown (at most a day) runs from
     # registration and from each update.
     decdn node update-multiaddrs{{ $flags }}

  Without --multiaddr, `decdn setup` registers the public address of the
  machine it runs on (if it has one), which is not this node's, and the
  cooldown then delays the correction: get the address right the first time.
